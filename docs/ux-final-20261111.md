## 部署步驟

1. 使用獨立 TWD Supabase 測試專案與 Streamlit App。`app.py`／`app_cmms.py` 是 CMMS UAT，不能當作本次 TWD 的等價環境。
2. 核對主表 `public.issues_prod` 與展延表 `public.twd_due_date_extension_requests`。RPC 固定使用這兩表；若使用自訂表名，需先對應修改並重新測試。
3. 保留原程式版本及資料庫備份；核對 `issue_id` 唯一、`due_date` 可接受 ISO 日期、`updated_date` 與現有文字時間格式相容。
4. 全新測試專案先套用 `sql/twd_due_date_extension_requests.sql`；已有展延表的專案直接執行 `sql/twd_ux_setup.sql`。
5. Setup 會建立文件索引表、private bucket、兩個期限 RPC，並允許展延紀錄的原期限為 NULL。整份 setup 由交易包住，確認執行成功才繼續。
6. 沿用 Secrets：`SUPABASE_URL`、`SUPABASE_KEY`、server-only `SUPABASE_SERVICE_ROLE_KEY`、`QAV_DUE_DATE_PASSWORD`。不要把值放進 Git。
7. 入口使用 `app_prod.py`，採 Python 3.13、本次固定版 `requirements.txt` 與 `.streamlit/config.toml` 的 10 MB 上傳限制。
8. 在測試環境重做草稿、期限核准／駁回、圖片及 XLSX／PDF 上下載；確認 service role 可執行 RPC，anon/authenticated 不可直接執行，bucket 保持 private。
9. 測試環境驗收後，才在已確認的正式專案套用 SQL 並部署程式。請使用者先完成手上輸入，重新啟動服務會失去 session 草稿。

## 恢復方式

若新版介面出現問題，回復部署前的程式與套件版本。保留新文件表、private bucket 與期限紀錄，避免刪除已收到的附件或歷程；不要用刪資料方式回退。舊版不顯示新文件時，須保留後續下載或恢復新版的安排。

## 本機重跑

在專案根目錄，以 PowerShell 執行：

```powershell
& .\.codex_tmp\ux-venv\Scripts\python.exe -m pytest tests/test_twd_app.py tests/test_ux_acceptance.py --show-capture=no --tb=short -q
```

重建測試環境時，先建立 Python venv，安裝 `requirements.txt` 及 `pytest==9.2.0`。Streamlit AppTest 需要 Windows 本機 socket；若平台限制，使用該平台核准機制。

SQL 測試套件僅用於開發驗收，不是正式 App 依賴：

```powershell
npm install --prefix .codex_tmp/ux-review/pg --ignore-scripts --no-audit --no-fund @electric-sql/pglite@0.5.16
node tests/sql_ux.mjs
```

預期 Python 33 項與 SQL 20 項通過。後續程式變動須重新測試。
